Напиши бриф карточки «{title}» (`{card}`) в репе `{root}`.
Тело карточки лежит ниже, в этом промпте.

1. Кроме случая `blocked`, предпоследним действием закоммить бриф в текущую ветку: `git add <путь>`, затем `git commit -m "docs(brief): <slug>"`.
2. Последним действием запиши в `{result}` строку `brief = "<путь к брифу от корня репы>"`.

Сначала прочитай файл `{answers}`. В нём ответы владельца на прошлые вопросы. Файла может не быть.

Ты уже в корне репы: запускай команды из него, без `cd` и без `git -C`.
Список разрешений по умолчанию даёт Bash запускать эти команды, по одной за вызов: `git status`, `git status --short`, `git log --oneline -20`, `git log -5`, `git diff`, `git diff --stat`, `git diff --cached`, `git add <путь>`, `git commit -m "<сообщение>"`, `nod …`.
Файлы читай и ищи инструментами Read, Grep и Glob.
Отказ в команде не останавливает бриф: сделай то же разрешённой командой или инструментом.

Перед вопросами прочитай `README.md`, `CONTEXT.md`, `.nod/cards/` и `docs/`.
Если ответ есть в репе, не задавай вопрос.

Бриф пиши по шаблону ниже, все десять разделов.
Файл клади в `docs/briefs/<дата>-<slug>.md`.

Шаблон брифа:

```
# <Заголовок боли в 4–8 словах>

Дата: YYYY-MM-DD. Статус: черновик | одобрен YYYY-MM-DD | отклонён | отложен | разрезан YYYY-MM-DD.

## 1. Боль
<Цитата владельца, как сказал.>

## 2. Вердикт
Делать | Не делать | Отложить. <Одна строка почему.>

## 3. Цена
Карточек: N. Часов рана: <по карточке через запятую, например 2, 3, 1>. Платные сервисы: нет | <какие>.

## 4. Решения
1. <Решение.> Почему: <одна строка>.
2. Вопрос: <формулировка>? Предлагаю: <ответ>. Почему: <причина>. Варианты: <вариант> | <вариант>.

## 5. Для пользователя
- <Что он увидит иначе.>

## 6. Для системы
- <Схема, API, инфраструктура.>

## 7. Риски
- <Риск.> Если сработает: <что сломается>.

## 8. Поддерживать дальше
- <Сервис, подписка, контракт данных, который появится и останется.> | Ничего.

## 9. Как проверим
Аккаунт: <какой>. Шаги:
1. <Действие.>
2. <Действие.>
Увидеть: <что>.
Для числа: метрика <имя>, сейчас <значение>, порог <значение>.
Оставь одно: шаги для сценария или строку метрики для числа. Для API вместо аккаунта — запрос.

## 10. Карточки
1. <Заголовок карточки в императиве, без точки>
2. …

Вне рана: <кто> — <что>.
```

Вопросы владельцу задавай только строками `Вопрос:` в разделе 4. В ответе в чате вопросов не задавай.
Форма строки: `N. Вопрос: <формулировка>? Предлагаю: <ответ>. Почему: <причина>. Варианты: <вариант> | <вариант>.`
Поле «Предлагаю:» обязательно. Предлагай самый вероятный ответ.
Начинай формулировку вопроса с заглавной буквы.
В «Варианты:» пиши только другие ответы. Предложенный ответ встанет первым сам, не повторяй его другими словами.

Если брифу нужно то, что может дать только владелец, не гадай и не спрашивай в чате.
Только владелец даёт вход, ключ API, тестовую карту. Только владелец поднимает упавший стенд.
Тогда запиши в `{result}` одну строку и остановись:
`blocked = "<что нужно от владельца, одной фразой>"`

Внимание: драйвер сам заведёт решение `owner-action` из строки `blocked =`. Если ты записал `blocked`, команду `decision ask` не запускай: решений станет два.

Не делай push.
В чат ответь одним словом.
Последние два действия — коммит `docs(brief): <slug>` и строка `brief = "<путь к брифу от корня репы>"` в `{result}`.
