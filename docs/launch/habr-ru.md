# Статья для Хабра

Черновик, не опубликован. Хабы проверить перед публикацией: «Open source», «Python», «Искусственный интеллект».

## Заголовок

Nod — очередь решений для проекта, который ведут агенты

## Текст

Nod — открытый инструмент (лицензия MIT) для проектов, которые ведут агенты Claude Code. Агенты пишут брифы и код и сами проверяют результат. Владельцу проекта остаются решения: какой из вариантов взять, принять ли готовую работу, что сделать руками, когда агент упёрся в логин или ключ API.

Репозиторий: https://github.com/maksim9980/the_nod

### Зачем

Агент в чате доводит задачу до коммита, только человек всё это время сидит рядом: отвечает на вопросы, смотрит, что вышло, просит переделать. Nod выносит работу из чата в очередь. Задачи лежат карточками, процесс-драйвер гоняет по ним агентов, а владельцу приходит то, что без него не решить.

Одно правило Nod держит жёстко: на решение отвечает только владелец. Драйвер не отвечает никогда. Агенты, которых он запускает, получают переменную `NOD_AGENT=1`, и под ней `nod decision answer`, `nod accept`, `nod card close` и ещё несколько команд отказывают с кодом 2. Инструменты MCP для тех же команд отказывают так же.

### Как устроено

У Nod три части.

- Ядро — команда `nod` на Python 3.13, только стандартная библиотека. Ядро хранит состояние файлами в папке `.nod/`, и только оно их пишет. Карточки и решения — Markdown с заголовком TOML. Каждая запись — коммит с темой `state: …`, поэтому история проекта читается через `git log`.
- Драйвер — процесс `nod driver` на машине владельца. Он берёт следующую карточку и запускает `claude -p`: написать бриф, сделать шаг, проверить результат. Его можно гонять по одному проходу командой `nod driver once` или поставить в автозапуск при входе в систему.
- Клиенты: панель в Claude Code, `nod status` в терминале и MCP-сервер для агентов. Панель читает снимок `.nod/state.json`, а ответ записывает той же командой `nod decision answer`, какой пользуется человек в терминале.

Карточка проходит один и тот же цикл.

1. Бриф. Агент пишет бриф: боль, цена, решения, риски, как проверить результат и пронумерованные шаги. Бриф ложится коммитом в `docs/briefs/`.
2. Развилки. Каждый открытый вопрос брифа становится решением с предложенным ответом. Если взять все предложения, карточка готова к работе. Если ответить иначе, агент перепишет бриф с учётом ваших ответов.
3. Шаги. Драйвер выполняет шаги по одному. Каждый шаг — отдельный запуск агента, одна команда `claude -p`. Агент коммитит код в рабочую ветку.
4. Приёмка. После последнего шага агент идёт по разделу брифа «Как проверим» и записывает итог: решено, не решено или не проверено.
5. Вердикт. Владелец закрывает карточку или возвращает её с заметкой. По возвращённой карточке агент напишет новый бриф, или она уйдёт в конец бэклога, как решит владелец.

Кроме развилок и вердиктов, драйвер спрашивает владельца, когда нужен он сам (на панели это пометка «Нужно действие»: войти в `claude`, положить ключ API, поднять упавший стенд), когда запуск агента завис и когда бэклог пуст («Бэклог пуст. Что болит?»). Панель показывает открытые решения в зоне «Ждёт тебя», ответ записывается кнопкой. Без панели то же самое делают `nod status` и `nod decision answer` в терминале.

#### Git

Nod пишет состояние только в рабочей ветке, `main` и `master` он отказывается трогать. По умолчанию Nod вообще не ходит в remote: ни pull, ни push, ни fetch. Ключ `[git] push = true` в `.nod/harness.toml` включает синхронизацию для двух машин: pull перед каждой записью, push после неё, и замок драйвера тогда переезжает через git.

#### Права агента

Драйвер запускает `claude -p` с моделью `sonnet`, в режиме `acceptEdits` и со списком разрешённых команд. В списке — git только для чтения в нескольких фиксированных формах, `git add`, `git commit`, `nod` и `python -m pytest` (или `python3 -m pytest`) на шагах и приёмке. `git push` в нём нет. Править `.git/`, `.claude/` и файлы состояния в `.nod/` агенту запрещено. Хуки git на время команды отключены. До и после каждой команды драйвер сверяет хуки, конфиг git, манифест и незакоммиченные правки в `.nod/`. Часть находок драйвер откатывает сам, о других только сообщает. На большинство находок он заводит решение владельцу: в нём сказано, что возвращено на место или что проверить и убрать самому. Песочницы при этом нет: агент может написать тест, и `pytest` запустит его с правами вашего пользователя. Полный список — в [SECURITY.md](https://github.com/maksim9980/the_nod/blob/main/SECURITY.md).

#### Язык

По умолчанию Nod говорит по-английски. Строка `lang = "ru"` в `.nod/harness.toml` или переменная `NOD_LANG=ru` переводят на русский CLI, лог драйвера, промпты агентов и панель.

### Полевой прогон

Цикл целиком проверили на проекте, которого Nod раньше не видел. Роль владельца играли вручную: на решения отвечали командой `nod decision answer`.

Проект — [astpretty](https://github.com/asottile/astpretty): MIT, около 500 строк Python без зависимостей, 22 теста на pytest. У клона сразу убрали `origin`, работа шла в новой ветке `nod-field`, через pip не ставилось ничего — ни Nod, ни сам проект. Окружение: Windows 11, Python 3.13.7, Claude Code 2.1.306, модель `sonnet`.

Карточка была одна: «Add a --version flag to the CLI». Команда `astpretty` должна принимать `--version`, печатать имя программы и версию и выходить с кодом 0.

Как шло:

- Первый бриф дал три шага и одну развилку: что печатать, если пакет не установлен и программу запускают из клона. Агент предложил не перехватывать `PackageNotFoundError`. Владелец выбрал другой вариант — печатать `astpretty unknown`. Драйвер отправил карточку на повторный бриф, и агент переписал тот же файл брифа под ответ.
- Второй шаг остановился на первых двух вызовах Bash. Агент начал с `cd <repo>; …; git log --oneline | head` и `git -C <repo> status --short`. Claude Code отказал в обоих, а в тексте отказа сказано, что всё, что требует одобрения, будет отклонено до конца сессии. Агент записал `stop`, карточка вернулась. Промпты не говорили агенту, что он уже стоит в корне репозитория и какие команды пропустит allowlist. Промпты поправили, владелец ответил `rerun`.
- После нового брифа третий шаг упёрся в тест, которому нужен установленный пакет. Pip агенту не разрешён, снова `stop`. Здесь ошибся бриф, ядро ни при чём. Стоп вернул карточку, и владелец ответил `rerun` с заметкой: пакет не ставить, в тесте подменить `importlib.metadata.version`.
- Третий повторный бриф переписал раздел проверки под клон без установки. Дальше шаги прошли, приёмка дала «решено», владелец принял, карточка закрыта. В проекте появился `--version` с запасным `unknown` и два новых теста, все 24 теста проходят.

Цифры:

| | |
|---|---|
| Команд агента под драйвером | 15: 4 брифа, 10 запусков шагов, 1 приёмка |
| Их стоимость | 3,27 USD |
| Одна команда | от 0,18 до 0,30 USD |
| Проход `nod driver once` с агентом | от 21 до 52 секунд |
| Вместе с ручной пробой вне драйвера | 3,54 USD при лимите прогона 40 USD |

Из четырёх брифов три повторных: после ответа на развилку и после двух стопов. Первый запустился случайно — об этом первая ошибка в списке ниже.

Сеть. `git remote -v` был пуст весь прогон. В `.nod/driver.log` нет ни push, ни pull, ни fetch. В 46 вызовах Bash у агентов нет ни `git push`, ни `pull`, ни `fetch`, ни `remote`.

Что сломалось и что починили:

1. `nod driver once --dry-run` запускал настоящий проход. `--dry-run` работает только с `install` и `uninstall`, а справка показывала его рядом с `once`. Проход, задуманный как просмотр, потратил 0,30 USD на настоящий бриф. Теперь такой вызов отказывает с кодом 2, и агент не стартует.
2. Промпты не называли разрешённые команды. Теперь называют, просят работать из корня без `cd` и `git -C` и говорят, что отказ в одной команде шаг не заканчивает. Тест следит, чтобы список совпадал с allowlist. После правки в 11 командах агента случился один отказ: приёмка попробовала запустить саму программу и дальше пошла по тестам.
3. Причина стопа доходила до повторного брифа подписанной как «заметка владельца», хотя владелец её не писал. Теперь драйвер кладёт свой текст в поле `reason`, поле `note` остаётся за владельцем.
4. `nod init` молча оставлял правку `.gitignore` незакоммиченной. Правку он по-прежнему оставляет владельцу, но теперь пишет об этом.

Что прогон показал про окружение. Агенты загружают ваши собственные настройки Claude Code: глобальный `CLAUDE.md`, плагины и хуки. На машине прогона глобальный плагин ревью безопасности запустил 4 лишние сессии на другой модели, около 70 000 токенов, и строки расхода Nod их не видят. У 10 агентов из 15 ответы в чате пришли на другом языке, файлы при этом остались английскими. Флаг `--setting-sources project` в ваших командах манифеста не пускает в агента пользовательские плагины и хуки.

Что прогон не проверял: панель на экране, две машины с `push = true`, автозапуск драйвера, бриф со стопом `blocked`, решение «Нужно действие» и зависший запуск агента. Полный отчёт, проход за проходом: https://github.com/maksim9980/the_nod/blob/main/docs/field-test.md

### Ограничения

- Только Claude Code. Драйвер запускает `claude -p`, панель — мод Claude Code. MCP-сервер работает через stdio, с Codex его не проверяли.
- Панель построена на API модов Claude Code. Этот API новый и может меняться от версии к версии.
- Первый клик по панели только переводит на неё фокус, нажимает кнопку второй клик. Это баг самого Claude Code, описание для его разработчиков: https://github.com/maksim9980/the_nod/blob/main/docs/bugs/2026-10-21-pane-first-click-focus.md
- Nod запускался на Windows 11. На Linux под WSL живьём прогнали тесты ядра — на Python 3.12, ниже требуемой 3.13, — и проверили, что автозапуск ставится и снимается (`systemd --user` и crontab). Запуск драйвера при входе в систему и после перезагрузки не проверяли. На macOS Nod проверен только тестами. На macOS и Linux MCP-серверу плагина нужна команда `python`, а там часто есть только `python3`; `nod doctor` это показывает.
- Запуски агента стоят денег. Бриф, шаг и приёмка — по одному вызову `claude -p` за счёт вашего плана Claude Code или аккаунта API. Лимит на вызов по умолчанию: 5 USD на бриф, 30 на шаг, 10 на приёмку. Nod не считает, сколько тратят ваши глобальные плагины и хуки в агентах.
- `claude -p` ничего не печатает до конца команды, поэтому медленный бриф от зависшего драйвер не отличит. Бриф или приёмку, которые молчат 40 минут, он останавливает.
- Приёмка по умолчанию запускает `python -m pytest` или `python3 -m pytest` и не может запустить собственную команду проекта. Для этого нужна своя команда `accept` в манифесте.

### Как попробовать

Нужны Claude Code, git и Python 3.13 или новее в PATH под именем `python`.

```
claude plugin marketplace add maksim9980/the_nod
claude plugin install nod@nod
```

В Claude Desktop, на вкладке Code, `/plugin` не работает. Там нажмите «+» рядом с полем ввода, откройте Plugins, добавьте маркетплейс `maksim9980/the_nod`, потом плагин `nod`, и перезапустите Desktop.

Дальше в своём репозитории:

```
git switch -c nod-work
nod init
git add .gitignore
git commit -m "chore: ignore Nod local files"
```

Nod по умолчанию говорит по-английски. Чтобы панель, CLI и промпты агентов были на русском, замените в `.nod/harness.toml` строку `lang = "en"` на `lang = "ru"` и закоммитьте манифест. Без этого панель подписана по-английски: «Waiting for you» вместо «Ждёт тебя», «Action needed» вместо «Нужно действие».

Потом карточка и первый проход драйвера:

```
nod card add "Export habits to CSV" --body "Хочу выгружать привычки в таблицу."
nod driver once
```

Команда `nod` в терминале появляется после `pipx install the-nod`. Без неё наберите `/nod` в сессии: вторая строка ответа — команда, которой запускать ядро. `/nod init` в сессии делает то же, что `nod init`, и сразу открывает панель. Дальше гоняйте `nod driver once` проход за проходом и отвечайте на то, что появится в «Ждёт тебя». Если кто-то из агентов упрётся в то, что можете сделать только вы, на панели появится решение с пометкой «Нужно действие».
